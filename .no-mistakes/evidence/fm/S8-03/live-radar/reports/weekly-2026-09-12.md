## Executive summary

control-plane foundation and two bounded research candidates. Lalo already
has contract-first engineering, exact-commit validation rules, hierarchical
dispatch, and real browser checks. The new evidence does not justify broad
autonomy or a provider switch. It supports a beta-only ponytail comparison,
rejects the caveman proxy on security and licensing grounds, and keeps Grok
4.7 on a dated release watch.

This report covers the gap since the 2026-08-08 baseline. It uses the
existing source registry and the 2026-09-10 lookout design evidence, with
direct source URLs retained below. No Firecrawl search or scrape was used.
The radar remains proposal-only against the fleet.

## Findings

### 1. Ponytail: `experiment`

Ponytail adds a concrete generation-time simplicity ladder, subagent
instruction injection, and a review skill. Its own benchmark reports lower
lines, tokens, cost, and time on a narrow task set, while also documenting
model sensitivity. Lalo already has stronger contract, test, browser, and
release controls in
`/home/rich/firstmate/projects/lalo-platform/docs/agent-ops/product/lalo-app/function-and-module-contract-standard.md`;
the unresolved question is whether the extra prompt discipline reduces
overbuilding without weakening required module boundaries.

Smallest experiment: run six duplicated historical ship tasks in an isolated
beta home, two member UI tasks, two admin tasks, one brain task, and one
firstmate script task. Keep the default lane and ponytail lane on the same
base SHA, same hour, local-only mode, and no production writes.

Validation and success measure: record quota delta, wall time, lines changed,
human touches, lint and test results, Astra judge score from 0 to 5, contract
boundary decisions, and any ponytail deferrals. Adopt only if ponytail wins
cost and lines on at least four of six tasks without judge-score loss or a
contract violation. Roll back by deleting the beta installation and retaining
the result report; no production configuration changes.

### 2. Caveman proxy: `reject`

Caveman's proxy targets expensive tool input and stores exact originals for
recovery. That storage is a material trust boundary because agent inputs and
tool results can contain credentials or personal data. The repository also
documents anonymous telemetry and a BSL-licensed engine. Lalo's current
firstmate boundary, Beanbot local-first data policy, and existing browser
tooling do not justify placing such a proxy in a fleet host's provider path.

Smallest bounded fallback, only if measured input-token cost later dominates:
run five duplicated log-heavy tasks in a disposable beta home with telemetry
disabled, no fleet credentials, and explicit deletion of the recovery
database after capture. Validate provider input tokens, judge quality,
latency, and any recovered sensitive content. Stop on any leakage, quality
loss, or unexplained proxy error. Roll back by removing the beta home; do not
install the proxy on a primary or mate host.

### 3. Hierarchical ownership and durable contracts: `already-covered`

The external evidence reinforces practices Lalo already implements rather
than exposing a new gap. `/home/rich/firstmate/config/crew-dispatch.json`
routes by task class, while
`/home/rich/firstmate/projects/lalo-platform/docs/agent-ops/AGENTS.md`
requires provider-neutral roles, isolated work, exact-SHA evidence, and
explicit PR communication. The contract standard joins prose, types, tests,
risk class, and module-boundary decisions. The current `llalo` CI also runs a
real guest browser smoke instead of treating command availability as product
verification.

No experiment or rollout is proposed. Recheck this classification when an
external source presents a measured result that exceeds these controls, and
deduplicate against `no-flat-swarm-default`, `truthful-verification-state`,
and `deterministic-product-verification` in `state/decisions.json`.

### 4. Grok 4.7 release watch: `watch`

The 2 September public expectation points to 12 September, but xAI and Cursor
had not published a confirmed model identifier, price, or model card by the
research cutoff. The model guide therefore records Grok 4.7 as its first
watch entry, due 2026-09-12, with validator then coder as the first case.

Smallest experiment when the model appears: run the fixed six-task set against
`gpt-5.6-luna-high`, first as a validator over the same merged diffs and then
as a coder. Capture quota, time, human touches, lint and tests, and Astra's
quality score. Success requires no quality or safety regression and a
measurable cost or time advantage on at least four of six tasks. Risk is
model-id, pricing, or quota uncertainty; rollback is deleting the candidate
lane and leaving the shared no-mistakes pin unchanged.

### 5. Model and effort guide: `partial`

The fleet has current runtime intent in
`/home/rich/firstmate/config/crew-dispatch.json`, but the dispatch file is
human-readable and the quota catalog is not a durable evidence table for the
models and effort levels the fleet actually uses. The radar now supplies
`config/model-guide.json` and a validated `model-guide` report type. The
remaining gap is operational: the platform mate must cite the guide when
regenerating dispatch rules and benchmark the entries before changing a
default.

Smallest experiment: use the six-task set to compare the current Luna high
profile with one candidate entry, serializing runs so quota deltas do not
mix. Validation is the benchmark record plus a guide entry with model id,
effort, roles, approval date, cost basis, evidence URLs, and SHA. Success is
an inspectable recommendation with no unmeasured quota or quality regression.
Risk is stale pricing or provider catalog drift. Rollback is to keep the
existing dispatch rule and mark the guide entry watch-only.

## Contrarian views and risks

Ponytail's published result is not a fleet result. Its benchmark uses a
limited task set and reports model sensitivity, so a lower token count can
still produce a worse contract boundary or more human repair. Caveman may
reduce large log inputs in some cases, but a proxy that stores exact
requests and results increases the blast radius of any local compromise.

The current browser CI evidence is stronger than the baseline's old snapshot,
but it does not prove all signed-in journeys or production writes. A guest
smoke must not be described as member or admin acceptance. Model guide prices
remain unverified until the provider's own pricing page is checked.
